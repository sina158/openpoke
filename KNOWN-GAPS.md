# Known gaps

Ranked, most serious first. One line each: the gap, then the fix.

## Open

1. **No auth on the HTTP API.** The server binds `0.0.0.0` by default (`OPENPOKE_HOST`), CORS is `*` by default, and `DELETE /chat/history` wipes everything with no check (`server/routes/chat.py`). Fix: an auth dependency on every route, default host `127.0.0.1`, a CORS allowlist.
2. **Cross-client messaging is reduced, not closed.** The v2 shared-client check (c1) refuses a turn's sends only when the targets look like the SAME client (shared multi-word name, email or id), and it is inert below 100 agents (fixed 2% document-frequency cut-off). On the fresh set at N=500 fix v2 still sent to two clients in 19 of 312 turns (B2a, fail) and reached another client's agent in 11 of 252 should-reuse case-trials (B2b, fail); `evals/results/RESULTS_v2.md`. The opt-in client guard (v2.1, `OPENPOKE_CLIENT_GUARD=1`, off by default) refuses such sends: on a held-out set it sent to two clients in 0 of 104 turns and reused another client's agent in 0 of 84, but refused three parallel cases whose message describes one client instead of naming it (G-iv fail; README, Client guard). Fix: count a description that fits one client's cards as naming that client, then measure on a new set.
3. **A draft send is bound to the draft id, not its contents.** `GMAIL_SEND_DRAFT` carries only `draft_id`, so the draft can be edited in Gmail after approval; the summary says "draft contents not shown" (`gmail.summarise_send`). Fix: fetch the draft when proposing, hash recipients, subject and body, re-fetch and compare before sending.
4. **The user sees a pending send through the model.** The summary and code are built in code, but reach the user inside the model's own reply; with two sends pending, which one a reply approves rests on the model relaying the right code next to the right summary. Fix: show pending actions in the UI straight from the approval store, one confirm control each.
5. **Single tenant by construction:** one registry, one conversation log, one Gmail user id; the `owner` column exists but nothing reads it. Fix: a tenant key on every store and route.
6. **No per-agent lock:** a trigger fire and a user follow-up can run the same agent at the same time. Fix: one asyncio lock per agent id in the batch manager.
7. **Retries outside email can repeat a side effect:** the single-use approval makes email at-most-once; any other tool that times out after acting and is retried acts twice. Fix: an idempotency key per tool call and an outbox.
8. **The summariser can carry email text into the user's "Preferences & Profile" memory** (`server/services/conversation/summarization/prompt_builder.py`). Fix: tag summary inputs by provenance and keep email and agent text out of profile facts.
9. **Every execution agent gets all 13 tools:** the same selection problem one level down. Fix: run the same selector over tool descriptions.
10. **At N=500 the shortlist does not make a turn cheaper in prompt tokens.** Fix v2 carries 58.5% of the baseline's prompt per model call but makes about 1.9 calls a turn, so a turn sends 103.0% of the baseline's (B5, fail); at N=5,000 (30 cases, one trial) a turn sends 15.6% of the baseline's (11,215 tokens against 72,091), but at about two calls a turn its p50 latency is about three times the baseline's (README, N=5,000). In the 30-day lifecycle run fix v2 sent 20,110 prompt tokens a turn against the baseline's 30,366. Fix: answer from the shortlist without a search round when a strong match is on it.
11. **One global batch:** a quick agent's result is held until every agent in the open batch has finished, each with a 90-second timeout (`server/agents/execution_agent/batch_manager.py`, `_complete_execution`). Fix: deliver each agent's result when it finishes.
12. **The Gmail watcher makes one LLM call per inbox email;** a broker inbox makes that a cost firehose. Fix: a rule prefilter and batched classification.
13. **Triggers re-fire after a crash and fire late after downtime.** Fix: persist the last fire time and define what happens to a missed window.
14. **Composio calls are synchronous on the event loop, and the 8-iteration cap ends a turn with an empty response** (`InteractionAgentRuntime.MAX_TOOL_ITERATIONS`). Fix: run the calls in a thread executor; tell the user when the cap is hit.
15. **Inherited third-party prompt text:** `prompts/interaction_full.md` (upstream, byte for byte), `prompts/interaction_shortlist.md` (a copy of it outside the rewritten paragraphs) and `server/agents/execution_agent/system_prompt.md` reproduce text from a leaked third-party assistant prompt. Fix: rewrite both prompts before any commercial use and re-run the eval.
16. **The duplicate check misses a duplicate that shares neither an id nor a similar name:** the name score caught none of the held-out duplicates at any threshold (`evals/results/DUPLICATE_THRESHOLD.md`); the shared-id check is what flags them (19 of the baseline's 27, round one). Fix: also match the client's names and emails from the instructions, behind the same confirm step.
17. **`cards._first_sentence` stops at an abbreviation** (`server/services/execution/cards.py`, `_SENTENCE_END` and `_first_sentence`): 14 case agents in the fresh set (targets or hard negatives, all in St. Catharines) have a purpose line that ends "... in St.", so their cards lose the city (counted from `evals/fixtures/agents_pool_v2.jsonl`), and the lifecycle scenario's "Billing problem for Mr. Delgado: ..." would become "Billing problem for Mr." (in the recorded lifecycle runs the model wrote its own instructions and no card was cut). Found by the blind review after the measurement was frozen; not fixed because it changes card bytes the recorded runs replay against. Fix: skip a match that ends in Mr., Ms., Mrs., Dr., St., Jr. or Sr., then re-record.
18. **The dataset is synthetic and template-clustered:** the fresh set is 110 cases from 19 templates, phrased by hand-written templates with no second-model phrasing pass; its 20-case hand check had a first pass by the owner's assistant and the owner's own check, and both agree on 20 of 20. Fix: a phrasing pass by another model family, a hand check of every label, then shadow mode on real traffic.
19. **The injection suite proves the gate, not the model:** a fake model makes exactly the attacker's calls. Fix: a live-model run over the same attacks.
20. **Clarification almost never happens.** On the fresh set fix v2 asked the user in 2 of 30 ambiguous case-trials (B4 fail), with 5 of 300 over-clarifications. With two claims for one client and no date it picked one claim every time; with two clients sharing a first name it messaged both agents on 8 of 15. deepseek-v4-pro under the same prompt asked on 5 of 10, so the rule depends on the model. Fix: return the question in code when two shortlisted agents fit the message equally, measured against the over-clarify rate.
21. **Every `should_create` fresh message says "new",** so hijack (B3) is measured only on cases where the user states it. Fix: add should_create cases that leave it implicit.
22. **The evidence arm cannot show retrieval here:** eval agent logs hold two entries, both already on the card, so it tests duplication; evidence is added outside the shortlist token budget; the v2 prompt explains neither `status="archived"` nor `evidence=`. Fix: longer logs in the fresh set and a prompt line for both attributes.
23. **Bounded execution memory (`OPENPOKE_EXECUTION_MEMORY=retrieved`) is covered by a unit test only** (`tests/test_execution_memory.py`: a 200-entry log goes from 5,190 to 246 history tokens); the routing eval stubs execution. Fix: score execution quality against history length.
24. **Cut for quota:** deepseek-v4-pro trials 2 and 3 (one trial only), the `cards_full` N=500 demo, the model-phrased set.
25. **Turns that end at the tool-iteration limit.** In the 30-day lifecycle run 52 baseline turns (4 under fix v1, 0 under fix v2) hit the limit and ended with no final reply; each had already sent to an agent, so they are graded like any other turn (`evals/results/RESULTS_v2.md`, lifecycle). Fix: item 14's message to the user, and count these turns as their own failure.
26. **The demo does not exercise the gate's refusal:** on its phishing turn the model never called `confirm_action`, so the forward was held only because nothing asked for it (`evals/results/TRANSCRIPT.md`, turn 7). The refusal is tested by the injection suite and `tests/test_send_gate.py`. Fix: a demo turn where the user answers the phishing email without the code.
27. **`conversation_limit` is wired but unset by default,** so an execution agent still carries its whole history. The lifecycle run measures that prompt on day 30 (fix v2: 6 agents, about 5,488 tokens on average) but does not send it. Fix: choose a limit by measuring execution quality against history length.
28. **No run used the repo's default model** (`anthropic/claude-sonnet-4`): there was no key for it. Fix: run `make eval-live` with an OpenRouter key.
29. **The thread-id lookup pin was found while reading report-split selector results,** so the "with pins" selector numbers are not blind. The fresh-set routing runs use the pins and are blind; the offline selector eval was not rerun on the fresh set. Fix: rerun it there.
30. **Execution is stubbed in every eval:** the routing eval grades one decision per case and the lifecycle run grades routing over 158 turns, but nothing measures what the execution agent then does. Fix: shadow mode on real traffic.

## Closed since round one

- **The generator drew the policy line at random even when an agent's name hard-coded it.** The fresh set's generator (`World(seed, version=2)`) keeps the caller's line: 0 such mismatches in `evals/fixtures/agents_pool_v2.jsonl`; round one's files regenerate unchanged, so its 1,147 mismatched pool agents remain there (`evals/golden/LABELS.md`).
- **The 30-day lifecycle simulation was not built.** It is built and run for baseline, fix v1 and fix v2 (`evals/run_lifecycle.py`, `evals/results/LIFECYCLE.md`).

Six round-one items are not listed because each is now stated where it applies: the README's testing notes, DESIGN.md's approval-gate section and `tests/test_baseline_replay.py`.
